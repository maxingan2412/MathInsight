# 设计说明

本文说明数鉴（MathInsight）的数据结构、模型与各项分析的计算方法。所有方法都在 `mathinsight/` 下有对应实现，文中注明了模块位置。

## 1. 题库（`bank/`、`scripts/import_kb.py`）

每道题是 `bank/questions.jsonl` 中的一行，主要字段：

| 字段 | 含义 |
|---|---|
| `id` | `试卷号-题号`，如 `SH-2024-18` |
| `type` / `score` | 题型（填空、单选、多选、解答）与原卷分值 |
| `region` / `year` / `kind` | 地区、年份、类别（高考 / 模拟） |
| `stem_html` / `answer_html` / `solution_html` | 题干、答案、详解（HTML + LaTeX，含矢量图） |
| `sections` | 对应教材小节（书、节、名称、细项） |
| `units` / `theme` | 板块（14 个）与课标主题（预备知识、函数、几何与代数、概率与统计） |
| `competencies` | 六大核心素养权重，和为 1 |
| `tiyan_tag` / `tiyan` | 题眼：这道题的卡点，以及打通卡点的那一步 |
| `difficulty` | 难度先验（0~1），由题位给出，再由作答数据校准 |
| `verified` | 题干文字是否已与多个来源逐字核对 |

**素养标注**（`taxonomy.py`）：先由板块给出基线权重（例如解析几何以数学运算为主），再按题型（解答题加逻辑推理）和题眼关键词（「翻译」「存在」→ 数学抽象，「画图」「截面」→ 直观想象，「情境」→ 数学建模……）微调，最后归一化。

**扩充题库**：知识库新增一套试卷后，在 `scripts/import_kb.py` 的 `PAPERS` 列表里加一行，重新运行导入即可。

## 2. 班级数据（`io.py`）

老师用 Excel 即可维护，四个文件：

```
students.csv   id,name,class
exams.json     每次考试：id、标题、日期、阶段、题目列表（题号 + 本卷分值）
scores.csv     student,exam,qid,score,error      逐题得分；error 为错因，可空
comments.csv   student,date,text                 教师主观评价，可多条
```

错因取五类：计算失误、审题错误、思路缺失、表述不完整、知识遗忘。

## 3. 学情模型（`model.py`）

学生 s 在题目 i 上的得分率记为 x_si，模型为

```
x_si ~ σ( θ_s + Σ_u a_iu · δ_su − b_i )
```

* θ_s：总体能力；b_i：题目难度；
* a_iu：题目在各板块上的权重（主板块 1，关联板块 0.5，归一化）；
* δ_su：学生在板块 u 上相对自身总体水平的偏移。

参数带高斯先验，用梯度法求最大后验估计；解答题按分值加权。题目难度以历年高考题位为常模（先验较强），所以班级整体在某一板块上的落后会体现在 δ 上，而不会被「这道题本来就难」吸收。

把板块权重矩阵换成素养权重矩阵，就得到六大核心素养上的偏移 γ_sc。

对老师展示的**掌握度**是 σ(θ_s + δ_su − b̄_u)：该生做本板块典型高考题的预计得分率，其中 b̄_u 取题库中该板块高考题的平均难度。

## 4. 个体分析（纵向）（`analytics.student_profile`）

* 各板块掌握度，以及在班内的百分位；
* 强项与弱项：δ 最高、最低的板块（要求有足够题量作证据）；
* 六大素养掌握度，与班级均值对比；
* 历次考试的分数、名次与班级均分走势；
* 错因分布；教师评语自动打标签（`comments.py`：学习习惯、思维特点、心态三类）；
* 生成个性化建议：针对弱板块、最弱素养、最常见错因与评语标签。

## 5. 群体分析（横向）与归因（`analytics.class_overview`、`diagnose_unit`）

* 学生 × 板块掌握度热力图；每个板块全班分布与排名；
* **薄弱板块**：相对偏移 δ 的班级均值最低，且实际得分率低于全卷平均（两条同时满足，避免把「题简单但偶有失误」误判为弱项）；
* **成因判断**：两路证据交叉印证——
  1. 模型证据：全班在各素养上的平均偏移 γ̄_c，按本板块题目的素养权重加权，得到每个素养对失分的贡献；
  2. 教师证据：本板块错题上标注的错因分布（计算失误 → 数学运算，审题错误 → 数学抽象，思路缺失 / 表述不完整 → 逻辑推理）。

  两者归一化后合成，得分最高的素养即主要成因。若模型层面差异不明显，则只依据教师标注，并在结论中注明。
* 输出板块内得分率最低的教材小节，以及对应的教学调整建议。

## 6. 试卷分析与梯度组卷（`paper.py`）

* **单卷分析**：各板块分值占比与题库中历年高考平均分布对照；主题、素养占比；难度曲线；未覆盖、偏多、偏少的板块。
* **多卷对比**：板块 × 考试的覆盖矩阵、累计覆盖，找出几次考试都没考到的内容，保证多次考试的考查重点不重复。
* **阶段组卷**：按卷型模板（上海卷、新高考卷）逐个题位选题——
  * 难度曲线随阶段整体上移：基础（一模）→ 提高（二模）→ 拔高（三模）→ 冲刺（四模，整体略高于高考）；
  * 板块分值向高考分布靠拢，超出部分加罚；
  * 避开之前考过的题，只用已核对的题。

## 7. 个性化练习（`recommend.py`）

* 只练弱板块：取 δ 最低且证据充分的 2~3 个板块；
* **最近发展区**：每题用模型预测该生的得分率，优先选 60%~85% 的题——太容易是重复，太难会挫败；每组另配一道 40%~55% 的挑战题；
* 同一教材小节最多两题，已做过的题不推；
* **提示阶梯**：每题附三级提示——方向（题眼标签）→ 卡点 → 打通。学生卡住时逐级展开，提交后才看完整详解，避免「先看答案再假装会了」。

## 8. 变式题生成（`variants.py`，需配置大模型接口）

1. 把原题的题眼作为「核心想法」写进提示词。没有核心想法时，模型生成的变式往往只换数字，形似神不似；
2. 限定知识边界：只能用原题所在教材小节及更早学过的知识；
3. 指定难度方向：铺垫（降一级）、巩固（同级）、拔高（升一级，可借鉴强基计划的设问方式）；
4. 先验证再入库：模型同时给出答案和 Python 验证代码，运行通过才标记为已验证，最终仍由老师审定。

## 9. 网页端（`web/`）

纯静态页面，数据以 JS 文件随页面加载，双击 `index.html` 即可离线使用。包含班级总览、学生档案、横向对比、试卷分析、题库、学生练习六个视图；学生练习的进度保存在浏览器本地。
